Executive Summary: AcademiaPro is an enterprise-grade academic ERP and DBMS engineered strictly under relational theory and BCNF normalization. It replaces isolated spreadsheets with a centralized, ACID-compliant relational system spanning student lifecycle, grading, tuition invoicing, library circulation, inventory management, and an AI advisory sandbox.
Key Developments & Deliverables
1. 6 Logical Relational Schemas Production Model
• system_core: RBAC roles, user authentication, immutable forensic audit trail.
• academics: Departments, programs, semesters, teachers, courses, sections, enrollments, attendance, and decoupled assessments.
• finance: Fee tariff structures, automated semester invoices, payments ledger, and consolidated library/discipline fines.
• library: Book cataloging, physical barcode copies, circulation borrowing.
• inventory: Departmental labs, item procurement, POs, issuance tracking.
• ai: Read-only query sessions, query telemetry, Roman Urdu intent logs.
2. Full-Stack Web Portal & ERP Flask + Bootstrap 5
Dynamic responsive UI supporting multi-role logins (Admin, Teacher, Student, Accountant, Librarian). Equipped with real-time text filtering, batch enrollment operations, dynamic fee invoice generation, and attendance shortage alerts.
3. Security Shield & Threat Defense Cyber Protection
Integrated dynamic anti-bot CAPTCHA, sliding-window rate limiting (120 req/min), automated IP bans after 5 failed attempts, brute-force account lockout, and admin security alert polling.
4. Read-Only AI Assistant Sandbox NLP & Guardrails
Natural language and Roman Urdu query classifier (e.g. attendance shortage, fee defaulters, attack alerts). Sandboxed via dedicated view-only database privileges to prevent SQL injection.
Key Academic Learnings
Relational Decomposition & BCNF: Transitioned schemas from UNF to 1NF (atomic attributes), 2NF (eliminated composite partial dependencies), 3NF (transitive dependency removal), and certified BCNF (every determinant is a candidate key). Eliminated Insertion, Deletion, and Update anomalies.
ACID Concurrency & Transaction Control: Implemented row-level locking (SELECT ... FOR UPDATE) and PL/pgSQL triggers to handle simultaneous student enrollments, seat limits, and automated late-return fine generation.
Analytical SQL Views & Relational Algebra: Designed optimized views (v_student_transcript, v_defaulters, v_attendance_shortage) leveraging complex equi-joins, aggregations, and Cartesian product protections.
Dual-Engine Architecture: Learned high-performance PostgreSQL 16+ production setup alongside an autonomous zero-config SQLite3 transparent engine for portability.
